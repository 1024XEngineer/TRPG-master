# 公开物品、携带旅行与 NPC 叙事修复

背包内的公开传单曾因补全全名被规划防泄漏检查误拦；“带着青蛙去大厅”又暴露出青蛙类型和步骤边界问题，使首次抵达被叙述成重返。对话展示中，逐字旁白与 NPC 回复分走不同路径，导致人物台词抢在旁白前出现。

## 公开名称与规划失败

- 规划公开性检查与公开规划上下文对齐，覆盖场景、背包、地面物品、已知信息及公开历史和记忆正文。物品实例 ID 与 Canon 定义 ID 不同也不再使公开名称失效。
- 允许使用公开名称不等于公开关联秘密、内部 ID 或取得物品。隐藏信息正文和机器引用继续校验；叙事中的公开背包名称也使用同样的文字判断原则。
- 重试仍执行完整校验。结构或防泄漏失败明确告知行动尚未执行，避免误导玩家反复澄清已经清楚的意图；日志记录失败类别和尝试次数。

## 携带、旅行与地图

- 幸福蛙蛙村 3.0.16 中，蛙群是场景 object，单只青蛙是独立可携带物品。取得后通过既有物品效果进入当前角色的背包，放下仍使用同一实例；蛙群不整体移动，两者不配置 NPC 音色。当前个体建模复用单只 Canon 实例，不新增无限生成或群体数量拆分机制。
- 规划区分 NPC 随行与物品取得。逐步裁决只执行 `step.semantic_goal`，父目标用于解释指代与限定；下一步重新核对位置、背包与同行状态。
- 模型已消解的普通旅行若目标等于本步当前位置，且没有规则、检定、失败效果或其他副作用，共享处理将其归并为零写入裁决。服务端保存 `already_at_destination_id`，成功提交后传入叙事；恢复和重试时清除过期标记。真实往返照常执行，原地步骤后仍继续后续动作。
- 全部结果仅为当前地点确认时，正常输出“你已经在一层接待大厅了。”，使用公开地点名和已有称呼规则，不调用叙事模型。含真实取得、抵达、新线索或其他动作的回合继续走完整叙事。
- 没有位置变化的历史旅行事件不再投影为到访记忆。本轮真实到访已有提交证据，不再次作为以往到访记忆传入叙事，避免把刚发生的抵达当成过去经历。
- 新版继续使用 `see_reception_map` → `resort_map_layout` → `learn_locations_from_map` 的既有规则：进入大厅自动获知地图信息并公开楼层布局，无需额外主动读图。地图公开仍不等于获得上锁房间的通行权限。
- PR #528 的场景开场 NPC、物件和出口上下文覆盖不在本次调整范围内。

## 独立旁白与人物台词

- `narration.push` 与 `dialogue.npc` 共用按到达顺序处理的展示队列。旁白逐字展示完成后才提交其后的 NPC 回复，同时按相同顺序加入既有语音队列。
- 保留权威事件 ID 去重、独立 NPC 回复和历史恢复机制；同步到达的消息及重复推送也维持旁白在前的顺序。
- 主叙事提示及已有重试提示要求旁白与人物台词各自完整成句。旁白简洁交代动作、结果和必要现场变化，避免重复玩家的问题与等待台词接上的引语前缀；人物语气主要由台词表达。

## 验证

- 公开性与防泄漏回归 42 项；携带和逐步旅行的生产适配器与真实引擎回归 20 项，覆盖原地短句、恢复、真实往返、捕获检定成功或失败、背包实例复用、放下、后续观察及未知目的地保护。
- 后端相关回归集曾通过 264 项、跳过 1 项；上述旅行用例补齐后的独立运行通过 20 项。两组有重叠，不累加。
- 框架编排、模组与持久结果回归通过 84 项。
- 房间页面通过 99 项测试，含新增的逐字旁白及同步推送两种倒序回归，同时检查语音顺序和重放去重。
- 后端叙事相关用例通过 18 项（分组验证）。一次组合运行在主体归属用例等待，14 项通过后中断；该用例单独运行通过，其余 3 项 NPC 发布和恢复用例也通过。
- 前端 ESLint、TypeScript 与生产构建通过；后端 Ruff、格式和 Ty 检查通过；模组构建语义校验及运行能力审计通过。
- 测试使用脚本模型和隔离数据库；提示文风的实际效果仍需新回合体验确认。本机前后端健康检查返回 HTTP 200。

已有房间仍绑定原模组版本。验证新版青蛙建模和地图发布版本须新建 3.0.16 房间；本次没有迁移旧存档或改写已发布叙事。
